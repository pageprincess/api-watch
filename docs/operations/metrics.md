## 北极星指标

**活跃监控的 API**

为什么？
- 直接衡量交付的价值
- 每个 API 代表一个正在解决的真实问题
- 与留存和收入相关

**目标**: Day 30 达到 100 个活跃 API

## 质量指标

### 假阳性率
**定义**: 标记的破坏性变更实际上不是破坏性的
**目标**: <5%
**追踪**: 用户反馈"这实际上不是破坏性的"

### 假阴性率
**定义**: 错过的破坏性变更
**目标**: 0%（关键）
**追踪**: 用户报告"API 崩溃了你没告警我"

### 支持响应时间
**目标**: 所有邮件 <4 小时
**延伸**: 关键 bug <1 小时

## 仪表板设置

**工具**:
- Cloudflare Analytics（访客）
- D1 查询（内部指标）
- 现在简单的 CSV 导出

**查询**:

```sql
-- 活跃用户（最后 7 天）
SELECT COUNT(DISTINCT user_id) FROM api_checks WHERE check_date > DATE('now', '-7 days');

-- 平均每个用户的 API
SELECT AVG(api_count) FROM (SELECT user_id, COUNT(DISTINCT api_id) as api_count FROM monitored_apis GROUP BY user_id);

-- 监控 API 增长
SELECT DATE(check_date), COUNT(DISTINCT api_id) FROM api_checks GROUP BY DATE(check_date) ORDER BY DATE(check_date);
```

## 唯一重要的指标

**Week 1**: 注册用户（验证）
**Week 2**: 激活（产品有效）
**Week 3**: 参与（习惯形成）
**Week 4**: 收入（商业可行性）

**如果只追踪一个指标**: **活跃监控的 API**

它捕获一切:
- 获客 → 新 API 添加
- 激活 → 第一个 API 添加
- 参与 → API 定期检查
- 留存 → API 仍在监控
- 收入 → API → 付费用户

---

## 停止指标

**如果到 Week 4**:
- <5 总注册
- 或 <2 激活用户
- 或 $0 MRR 且 <10% 转化意向
- 或 >50% 抱怨"这不工作"

---

**Paul 的建议**:

> 指标应该驱动行动，不仅仅是报告。
>
> 每个指标应该有:
> 1. 目标
> 2. 当前值
> 3. 如果偏离目标的行动
>
> 如果 Day 7 留存 < 50% → 修复 onboarding
> 如果平均 API/用户 < 2 → 添加更多模板
> 如果转化 < 5% → 重新考虑定价或价值
