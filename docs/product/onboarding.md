# APIWatch 新手引导

**目标**: 让新用户在 5 分钟内体验到价值

---

## 引导流程设计

### 阶段 1：注册到第一个 API（2 分钟）

**页面流程**:

```
1. Landing Page
   ↓ [点击 "Start Free"]
   
2. Sign Up Form
   - 邮箱
   - 密码
   ↓ [创建账户]
   
3. Welcome Modal
   "欢迎！让我们添加你的第一个 API"
   ↓ [选择 "使用模板"]
   
4. Template Gallery
   [Stripe] [GitHub] [Slack] [OpenAI]...
   ↓ [点击 Stripe]
   
5. Success!
   "✅ Stripe API 已添加"
   "📧 检查邮箱看告警示例"
```

**关键 UX 原则**:
1. **单目标页面**: 每屏一个 CTA
2. **进度可见**: "Step 1 of 3"
3. **即时反馈**: 添加后立即确认
4. **无干扰**: 不显示定价、功能比较等

## 用户流失点

### 点 1：注册后未添加 API

**原因**: 
- 不理解产品
- 找不到 API spec URL
- 分心

**解决方案**:
- 在注册页显示"支持的 API"列表
- 提供"浏览 API"功能而无需注册
- 注册后立即引导："添加 Stripe 只需 1 点击"

### 点 2：添加一个 API 后离开

**原因**:
- "我只需要一个"
- 没看到即时价值
- 忘记了

**解决方案**:
- 24 小时内发送第一次"真实"检查
- 即使无变更也发送"无变更"报告（"一切正常 🎉"）
- 每周摘要："本周你的 API 变更了 X 次"

### 点 3：收到告警后离开

**原因**:
- 假阳性（烦人）
- 不知道如何修复
- 不是真的关心

**解决方案**:
- 每个告警有"修复指南"
- "这是真的有问题吗？"反馈按钮
- 调查：为什么他们不关心？

## 引导的"黄金法则"

1. **不要教育，要展示**
   - 坏："APIWatch 监控 OpenAPI 规范..."
   - 好："Stripe API 变更了，这里是你需要修复的代码"

2. **不要销售，要帮助**
   - 坏："升级到 Pro 获得无限 API！"
   - 好："你用了 2/3 API。升级获得更多。"

3. **不要假设，要问**
   - 坏:"用户肯定想要 X 功能"
   - 好:"你在使用中遇到什么问题？"

4. **不要自动化，要个人化**
   - 坏: 自动欢迎邮件（noreply@）
   - 好: 来自创始人的个人邮件

---

**Don Norman 的备注**:

> 好的 onboarding 是隐形的。用户不应该想
> "我在学习这个产品"，而是"我在完成我的任务"。
>
> 如果用户在 onboarding 中感到困惑或沮丧，
> 产品设计失败了，不是用户失败了。
