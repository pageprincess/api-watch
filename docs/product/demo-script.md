## 演示技巧

### 准备工作

1. **提前演示环境**：确保 Dashboard 有真实数据（模拟或真实）
2. **备份变更案例**：准备 2-3 个真实的破坏性变更案例
3. **准备问答**：预想 10 个常见问题

### 演示原则

1. **讲故事**：用真实事故故事开场，不是功能列表
2. **展示，不要说**：屏幕录制优于幻灯片
3. **保持简单**：3 分钟版本只讲核心功能
4. **互动**：问观众问题，不要独白

### 常见问题

**Q: 你们监控哪些 API？**
A: 任何 OpenAPI/Swagger 规范的 API。预置 10 个常见模板（Stripe、GitHub、Slack 等）。

**Q: 你们会调用我的 API 端点吗？**
A: 不会。我们只读取 OpenAPI 规范，不调用业务端点。

**Q: 如何定义"破坏性变更"？**
A: 基于 oasdiff 标准。删除端点、删除必填参数、修改参数类型等。

**Q: 误报怎么办？**
A: 用户可以标记"非破坏性"，系统会学习并改进。

**Q: 安全性？**
A: OpenAPI URL 通常是公开的。如果是私有的，我们支持 API Key 认证。
