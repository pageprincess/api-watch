# APIWatch 产品定位决策

**决策日期**: 2026-02-13
**决策者**: Jeff Bezos (ceo-bezos)
**基于**: Thompson 市场调研报告

---

## 产品定义（一句话）

**APIWatch 是 API 破坏性变更的 Canary 部署**——在第三方 API 变更破坏你的应用前，主动检测并告警你。

> 就像 Canary 部署在代码变更前检测问题，APIWatch 在 API 变更影响用户前检测破坏性修改。

---

## 目标客户（优先级）

### 1. 中小型 SaaS 团队（5-50 人）- 核心目标
**理由**：
- **痛点匹配度最高**：依赖多个第三方 API（Stripe、GitHub、Slack、OpenAI），API 变更导致生产故障是真实痛点
- **支付能力验证**：预算 $50-300/月，符合我们的定价区间
- **Postman 机会**：2026年3月 Postman 取消免费团队协作，这部分用户正在寻找替代品
- **决策快速**：小团队决策链条短，可以快速试用和付费

### 2. AI/ML 工程师 - 早期采用者
**理由**：
- **空白市场**：OpenAI、Anthropic 等 AI API 快速演进，无专门监控工具
- **技术敏感度**：更早理解 API 契约变更的价值
- **社区效应**：在 Reddit/r/LocalLLaMA、Hacker News 等社区活跃，传播快
- **迁移成本低**：个人或小团队试用决策快

### 3. 平台型公司（提供公共 API）- 企业级扩展
**理由**：
- **反向需求**：需要监控自己的 API 变更对集成者的影响
- **减少支持工单**：主动发现破坏性变更，减少"你的 API 改变了"投诉
- **预算充足**：愿意支付 $299+/月 的企业级价格
- **销售周期长**：放在 Day 30+ 优先级

### 4. 独立开发者 - 免费层用户
**理由**：
- **规模限制**：1-3 人团队，预算 $0-20/月
- **种子用户**：帮助产品验证和口碑传播
- **转化潜力**：部分独立开发者会成长为付费团队
- **社区影响**：在 Twitter、Reddit、Product Hunt 有传播力

## MVP 范围（Day 1）

### 必须有

#### 功能 1: 破坏性变更检测引擎
**描述**: 监控 OpenAPI 规范变更，智能区分破坏性变更和非破坏性变更
**为什么必须有**：
- 这是核心价值主张，没有它就没有产品
- 市场空白：Postman 检测宕机，Bump.sh 检测文档差异，但没有人专注"破坏性分析"
- 技术可行：可以基于开源工具 oasdiff 构建

#### 功能 2: REST API 监控（OpenAPI/Swagger）
**描述**: 定期拉取 OpenAPI 规范，检测端点、参数、响应结构的变更
**为什么必须有**：
- REST API 占据 90% 以上的市场
- OpenAPI 是事实标准，工具生态成熟
- 单一协议可以快速验证市场

#### 功能 3: 告警系统（邮件 + Slack）
**描述**: 检测到破坏性变更后，自动发送告警到邮件或 Slack
**为什么必须有**：
- "检测"不等于"告警"，告警才是用户感知的价值
- 邮件是最低门槛，Slack 是开发者的默认工具
- 没有告警，用户还是需要主动检查，没有解决"悄然发生"的痛点

#### 功能 4: 单一端点监控模板
**描述**: 预置常见 API（Stripe、GitHub、OpenAI）的监控模板
**为什么必须有**：
- 降低设置门槛：用户输入 URL 即可开始监控
- 展示产品价值：5 分钟内看到第一个告警
- SEO 价值："监控 Stripe API"是搜索关键词

#### 功能 5: 免费层 + 单一付费计划
**描述**: Free（1 个 API，每日检查）和 Pro（$29/月，5 个 API，每小时检查）
**为什么必须有**：
- 免费层降低试用门槛，获取用户
- 单一付费计划简化决策（$29/月 vs $14-49/用户/月 的 Postman）
- 快速验证支付意愿

### Nice to Have（后续版本）

#### Phase 2（Week 2-4）
- GraphQL schema 监控
- Webhook 告警
- 变更历史时间线
- 团队仪表板

#### Phase 3（Month 2+）
- 自定义告警规则引擎
- API gateway 集成（AWS API Gateway、Cloudflare）
- SSO 和团队管理
- AI API 专项监控模板

## 定价策略

基于市场调研和目标客户支付意愿：

| Plan | 价格 | 目标用户 | 功能 |
|------|------|----------|------|
| **Free** | $0 | 独立开发者、试用用户 | 1 个 API 监控，每日检查，邮件告警，30 天历史 |
| **Starter** | $29/月 | 小团队（2-10 人） | 5 个 API 监控，每小时检查，邮件 + Slack 告警，无限历史 |
| **Pro** | $99/月 | 中型团队（10-50 人） | 25 个 API 监控，每 15 分钟检查，邮件 + Slack + Webhook，团队仪表板（10 用户） |
| **Enterprise** | $299+/月 | 大型企业 | 无限 API，自定义检查频率，SSO，专属支持，SLA |

### 定价逻辑

1. **$29 Starter** vs 竞品：
   - Postman Basic: $14/用户/月 × 5 人 = $70/月（我们便宜 58%）
   - Bump.sh: €249/月 ≈ $270/月（我们便宜 89%）
   - Checkly Team: $80/月（我们便宜 64%）

2. **按 API 数量，而非按用户**：
   - 与 Postman 的关键差异
   - 小团队有多个 API 但预算有限
   - 符合"API 供应链"的价值主张

3. **透明定价**：
   - 无"联系我们"
   - 无隐藏费用
   - 符合开发者工具趋势

## CEO 备注

### 给团队的建议

#### 1. 专注价值，而非功能
> "在开始写代码之前，先写 PR/FAQ。假设我们已经发布，新闻稿怎么写？用户会问什么？"
>
> MVP 的 5 个功能都是为"在 API 变更破坏应用前告警"这一价值服务的。任何不直接支持这一价值的功能，都是 Nice to Have。

#### 2. 快速决策，快速验证
> "大多数决策是双向门（可逆的）。如果 Starter $29/月 错了，我们可以在 2 周内调整。如果破坏性检测引擎方向错了，我们会在 Week 1 看到用户反馈。"
>
> 不要等到 90% 信息。70% 信息就足够行动。

#### 3. 不要和 Postman 正面竞争
> "Postman 是瑞士军刀，我们是手术刀。我们不做 API 测试、不做 Mock 服务器、不做文档生成。我们只做一件事：破坏性变更检测。"
>
> 这不是弱点，是差异化。

#### 4. 免费层是增长引擎，不是慈善
> "Free 层的 1 个 API 监控是获客成本。当用户的 1 个 API 挽回了一次生产故障，他们会升级到 5 个、25 个。"
>
> 参考 Dropbox、Mailchimp 的免费策略。

#### 5. Day 1 心态
> "永远保持创业第一天的心态。当我们有 100 个付费用户时，还是像对待第一个用户那样对待他们。"
>
- 每个 bug 都是紧急的
- 每个用户反馈都值得阅读
- 每个功能都要问"这会加速飞轮吗？"

### 风险预警

#### 风险 1: Postman 添加破坏性变更检测
- **可能性**: 低
- **缓解**: 专注第三方 API 监控（非自有 API），Postman 无此用例
- **CEO 优先级**: 监控 Postman 产品路线图

#### 风险 2: 开发者不在乎直到受伤
- **可能性**: 中
- **缓解**: 教育营销 + 免费试用降低门槛
- **CEO 优先级**: Week 1 的 Reddit/HN 发布是关键

#### 风险 3: 技术复杂度（diff 规范难）
- **可能性**: 低
- **缓解**: 站在 oasdiff 等开源工具肩膀上
- **CEO 优先级**: CTO 评估 oasdiff 集成可行性
